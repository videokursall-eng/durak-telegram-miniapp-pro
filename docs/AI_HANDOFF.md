# Как переносить проект между нейросетями (Cursor / Copilot / ChatGPT)

## 1) Источник истины — Git
- Проект живёт в репозитории.
- Любая нейросеть получает контекст из файлов: `docs/` + текущего кода.

## 2) Минимальный пакет контекста (всегда отправляй)
1) `README.md` (корень)
2) `docs/PRD.md`
3) `docs/RULES_DURAK.md`
4) `docs/WS_PROTOCOL.md`
5) `docs/STATE_MACHINE.md`
6) `docs/REWRITE-SCOPE.md` — что можно переписывать для Telegram-запуска, что нельзя
7) Файлы, которые прямо меняешь в задаче (или ссылку на PR/commit)

## 3) Шаблон задачи для любой нейросети
- Цель (1–2 предложения)
- Ограничения (стек, правила, нельзя ломать API)
- Список файлов, которые можно менять
- Критерии готовности (как проверить)
- Набор тест-кейсов

## 4) Как передавать “структуру проекта” в другую нейросеть
- Самый надёжный способ: дать “дерево” (`docs/REPO_STRUCTURE.md`) + ссылку на репо.
- Если репо приватное и ссылку дать нельзя — копируй:
  - дерево папок
  - `package.json`/workspace
  - ключевые интерфейсы типов и протокола

## 5) Пример “handoff message”
«Вот репо (дерево в REPO_STRUCTURE.md). Нужна реализация Task 03: WS join и снапшот. Протокол в WS_PROTOCOL.md. Игровые правила не трогать. Должно пройти: ws join → room.joined → state.snapshot. Сделай тестовый клиент или unit-тесты.»
