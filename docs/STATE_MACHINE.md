# State Machine — матч «Дурак» (простой + переводной)

## 1. Термины
- **Attacker** — атакующий (ходит на стол)
- **Defender** — защищающийся (отбивается/переводит/берёт)
- **Table** — карты на столе (пары: attack + optional defend)
- **Trick** — один “раунд атаки” до «Бито» или «Беру»

## 2. Высокоуровневые состояния матча
Ниже — конечный автомат (FSM). Сервер хранит `state.phase` и `state.turn`.

### 2.1 Состояния (phases)
1) `LOBBY`
- игроки подключаются к комнате
- готовность/таймер старта
- выбор режима: simple/transfer

2) `STARTING`
- создание колоды, тасовка, определение козыря
- раздача до 6 карт

3) `TRICK_ATTACK`
- атакующий выбирает 1 карту (или несколько только если правила позволяют в подкидывании — но на старте одна)
- после первой карты запускается ограничение по лимиту стола

4) `TRICK_DEFENSE`
- защитник:
  - покрывает каждую атакующую карту
  - или (в переводном) переводит
  - или берёт

5) `TRICK_THROW_IN`
- подкидывание:
  - атакующий и другие игроки (кроме защитника) могут подкидывать карты подходящих рангов
  - до лимита: `min(6, cardsInDefenderHandAtTrickStart)` (классическое правило)
- защитник отбивается по каждой новой атакующей карте

6) `TRICK_RESOLUTION`
- если все атакующие карты покрыты и больше нет подкидываний → `BEATEN`
- если защитник выбрал `TAKE` или не смог покрыть → `TAKEN`

7) `REFILL`
- добор карт из колоды до 6
- порядок добора: сначала атакующий, затем по кругу, защитник — последним (классика; можно параметризовать)

8) `NEXT_TRICK`
- назначаем нового атакующего/защитника
- проверяем окончание игры

9) `FINISHED`
- определён победитель(и) и проигравший (дурак)
- запись результата

## 3. Переходы (events → transitions)
### 3.1 LOBBY
- `room.ready` → если условий достаточно → `STARTING`

### 3.2 STARTING
- `match.start` → `TRICK_ATTACK`

### 3.3 TRICK_ATTACK
- `turn.attack(cards[])`:
  - валидировать: текущий игрок = attacker
  - валидировать: карты на руке игрока
  - валидировать: если стол пуст — любая карта
  - иначе — только ранги, уже присутствующие на столе (для подкидывания)
  - применить: положить на стол как attacking cards (без defense)
  - перейти → `TRICK_DEFENSE`

### 3.4 TRICK_DEFENSE
- `turn.defend(pairIndex, card)`:
  - валидировать: defender
  - валидировать: покрывает (по масти/козырю)
  - применить: добавить defense к выбранной attacking card
  - если всё покрыто и подкидываний больше нет → `TRICK_THROW_IN` (окно подкидываний) или сразу `TRICK_RESOLUTION` (если подкидывания отключены/все пас)
- `turn.transfer(card)` (только transfer):
  - валидировать: defender
  - валидировать: стол имеет ровно одну непокрытую attacking card ИЛИ политика перевода (см. RULES_DURAK)
  - валидировать: карта transfer совпадает по рангу с одной из атакующих карт
  - применить: добавляем карту как attacking, меняем defender на следующего игрока
  - фаза остаётся `TRICK_DEFENSE` (но для нового defender)
- `turn.take()`:
  - валидировать: defender
  - применить: пометить take → `TRICK_RESOLUTION`

### 3.5 TRICK_THROW_IN
- `turn.throwIn(cards[])`:
  - валидировать: не defender
  - валидировать: ранги присутствуют на столе
  - валидировать: лимит стола не превышен
  - применить: добавить атакующие карты → вернуться в `TRICK_DEFENSE`
- `turn.doneThrowIn()`:
  - когда все потенциальные подкидывающие “пас”
  - если все attacking покрыты → `TRICK_RESOLUTION`

### 3.6 TRICK_RESOLUTION
- если `TAKEN`:
  - все карты со стола уходят в руку defender
  - следующий attacker = тот же attacker (обычно атакующий снова ходит)
- если `BEATEN`:
  - все карты со стола уходят в discard (отбой)
  - следующий attacker = defender (защитившийся ходит)
- затем → `REFILL`

### 3.7 REFILL → NEXT_TRICK
- раздать добор до 6 из колоды в правильном порядке
- если колода пуста — добора нет

### 3.8 NEXT_TRICK → FINISHED
- игрок “вышел”, если в руке 0 карт и колода пуста
- игра заканчивается когда остался 1 игрок с картами → он “дурак”
- фиксируем результаты

## 4. Инварианты (must hold)
- Сервер единственный, кто меняет `GameState`.
- Каждое действие имеет `actionId` и применяется ровно 1 раз (idempotency).
- `GameState.version` увеличивается при каждом принятом действии.
- Клиент может запросить `sync.state` и восстановиться по snapshot.

## 5. Примечания по UX
- В UI всегда подсвечиваем attacker/defender и текущего активного игрока.
- Для defender показываем быстрые подсказки: “можно перевести”, “нет защиты — бери”.
